Color, type and component states

Principles

The palette starts from green and gold, deepened to work as interface color rather than flag color, joined by a blue as a third brand hue. All three live as identity — navigation, primary actions, categorization. The feedback colors (success/warning/danger/info) are a separate system: they reuse green and blue where the meaning already lines up, but warning and danger use their own hues, so "this is gold because it's the brand" is never confused with "this is gold because it's an alert."

Brand color

Each hue has a scale from 50 (lightest) to 900 (darkest). Step 500 is the base used for primary actions; the light steps (50–200) serve as backgrounds in light mode, the dark steps (700–900) serve as backgrounds in dark mode.

Why not white: a pure white app background makes the brand hues look harsh and screen-like next to a paper-toned brand voice. The cream base (#EFE3C6) keeps the same warm undertone as the dark mode's green-black, so both modes read as one family instead of "dark theme" and "generic light theme" bolted together.

Semantic colors

Success reuses Signal Green and Info reuses Deep Blue — the meaning already matches the brand. Warning and Danger are their own hues (burnt orange and terracotta), deliberately different from the brand's Ochre Gold, so "this is gold" is never read as "this is a warning."

Buttons — Bootstrap variants, themed

These are real Bootstrap 5 .btn classes, not bespoke ones — btn-primary is gold, btn-secondary is green, and the semantic variants (btn-success/warning/danger/info) match the feedback palette from earlier in this guide. Everything — resting, hover, active, focus ring, disabled — is themed through Bootstrap's own CSS custom properties, so it stays a normal Bootstrap button underneath: same markup, same JS, same accessibility behavior, only the color tokens changed.

Hover any of these — the shade darkens using the same 15%/20% hover/active mix Bootstrap applies to every variant, just computed from our hex instead of the Bootstrap defaults. Light and Dark are left as Bootstrap's own neutrals on purpose; they're utility, not brand. Link is set to Deep Blue — the one place a button is allowed to read as blue, because a link-styled button is a link.

Icon buttons — video player controls

Use icon-only buttons for compact, familiar player actions. They remain real Bootstrap .btn controls; .btn-icon only gives them a consistent 40×40px square hit area and centers the Bootstrap Icon. Every icon-only action must include an aria-label and a Bootstrap tooltip so meaning never depends on the glyph alone.

Dropdowns

A real Bootstrap .dropdown — click it, it opens and closes via Bootstrap's own JS. The trigger uses the reversed-gold outline button treatment; the open menu sits one step up from the page background, and the active item is picked out with a soft gold tint via --bs-dropdown-link-active-bg — never a filled row.

Cards

Real Bootstrap .card markup — .card-body, .card-title, .card-text — themed only by pointing --bs-card-bg at our surface color. Two shapes cover most of the library: a tall, cover-forward book card for a browsing grid, and a flat folder card for a horizontal shelf. Neither carries a filled button — the card itself is the click target.

Folders & book lists

Real Bootstrap .list-group / .list-group-item-action — the same row pattern serves both folders and books, using Bootstrap's own hover/active mechanics (--bs-list-group-action-hover-bg, --bs-list-group-active-bg) instead of bespoke CSS. Hover this list for real.

Interaction color: hover is always green, everywhere — rows, cards, menu items, and it's also the resting fill of the Secondary button. Gold stays reserved for the one Primary action per screen (and for .active here). Blue never appears as a hover or interactive surface color at all; it's kept small — a tag badge, a link, an info icon — never a background you mouse over.

Accessibility — contrast (WCAG)

Contrast ratios calculated for the most-used text/background pairs. Minimum for normal text: 4.5:1 (AA). Large text (≥18px, or 14px bold) accepts 3:1.

Usage — do / don't

✓ DO

Use Ochre Gold for brand actions and highlights — navigation, secondary button, categorization.

✗ DON'T

Don't use Ochre Gold to signal a warning state — use the orange from --color-warning instead.

✓ DO

Keep every button gold — filled for the one primary action, reversed for the rest. Keep the filled version's text fixed dark, in both modes.

✗ DON'T

Don't reach for green or blue to rank a second or third button — reverse the gold instead. And don't switch the filled button's text to white "to match" — it breaks the minimum contrast.
